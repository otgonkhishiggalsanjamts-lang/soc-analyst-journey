
# IR Playbook — SSH/RDP Brute Force → Compromise

## 1. Ерөнхий мэдээлэл

- **Playbook ID:** IR-PB-001
- **Халдлагын төрөл:** SSH/RDP Brute Force, Account Compromise
- **Хамаарах систем:** Windows Server, Linux Server
- **Хэрэгсэл:** Wazuh SIEM, Windows Event Logs, Sysmon, Linux auth.log
- **MITRE ATT&CK:** T1110 (Brute Force), T1078 (Valid Accounts)
- **Хариуцах баг:** SOC Tier 1, Tier 2, Incident Response Team
- **Зорилго:** Давтагдсан нэвтрэлтийн алдаа, түүний дараах амжилттай нэвтрэлтийг илрүүлж, зөвшөөрөлгүй хандалт болсон эсэхийг тогтоон, эрсдэлийг бууруулах.

## 2. Trigger — Playbook эхлүүлэх нөхцөл

Дараах нөхцөлийн аль нэг илэрвэл playbook-ийг эхлүүлнэ.

- Wazuh Rule 5712 — SSH brute force.
- Wazuh Rule 60204 — Multiple Windows Logon Failures.
- Нэг хэрэглэгч эсвэл эх IP-ээс олон удаагийн амжилтгүй нэвтрэлт бүртгэгдэх.
- Амжилтгүй нэвтрэлтийн дараа Windows Event 4624 эсвэл Linux SSH login success бүртгэгдэх.
- Амжилттай нэвтрэлтийн дараа сэжигтэй процесс, шинэ хэрэглэгч, scheduled task эсвэл SSH key нэмэгдэх.

**Анхаарах зүйл:** Alert илэрсэн нь дангаараа account compromise батлагдсан гэсэн үг биш.

## 3. Detection & Analysis

SOC Tier 1 дараах шалгалтуудыг хийнэ.

- [ ] Alert-ийн timestamp, agent.name, rule.id, rule.level-ийг бүртгэх.
- [ ] Эх IP, хэрэглэгчийн нэр, нэвтрэлтийн төрлийг тодорхойлох.
- [ ] Эх IP-г AbuseIPDB зэрэг Threat Intelligence эх сурвалжаар шалгах.
- [ ] Windows Event 4625 болон 4624-ийн дарааллыг харьцуулах.
- [ ] Linux auth.log доторх Failed password, Accepted password мөрүүдийг шалгах.
- [ ] Тухайн хэрэглэгч өөр хост руу нэвтэрсэн эсэхийг шалгах.
- [ ] Sysmon Event ID 1 болон Windows Event 4688-аар нэвтрэлтийн дараах процессуудыг шинжлэх.
- [ ] Event 4720, 4732 болон scheduled task-ийн бүртгэлийг шалгах.
- [ ] Scoping хийх: өртсөн хост, хэрэглэгч, өгөгдөл, бусад системийг тодорхойлох.
- [ ] Зөвшөөрөгдсөн администраторын үйлдэл эсвэл лабораторийн туршилт байсан эсэхийг баталгаажуулах.

### Шинжилгээний шийдвэр

- **False Positive:** Зөвшөөрөгдсөн үйл ажиллагаа нотлогдсон.
- **Suspicious:** Давтагдсан алдаа эсвэл failed-to-success хэв маягтай боловч compromise батлагдаагүй.
- **Confirmed Incident:** Зөвшөөрөлгүй хандалт болон түүнтэй холбоотой нотолгоо батлагдсан.

## 4. Containment — Тархалтыг хязгаарлах

### Богино хугацааны арга хэмжээ

- [ ] SOC Tier 2/IR Lead-д мэдээлэх.
- [ ] Зөвшөөрөлгүй нэвтрэлт батлагдсан дансыг эрх бүхий ажилтнаар түр түгжүүлэх.
- [ ] Шаардлагатай бол өртсөн хостыг сүлжээнээс тусгаарлах.
- [ ] Баталгаажсан хортой эх IP-г firewall-д блоклох.
- [ ] Нотолгоог хадгалж, хийсэн үйлдэл бүрийг бүртгэх.

### Урт хугацааны арга хэмжээ

- [ ] Account lockout бодлогыг шалгах.
- [ ] MFA нэвтрүүлэх эсвэл сайжруулах.
- [ ] SSH/RDP хандалтыг зөвшөөрөгдсөн хаяг, VPN-ээр хязгаарлах.
- [ ] Нэмэлт detection rule болон monitoring тохируулах.

**Анхаарах зүйл:** Бодит систем дээр данс түгжих, IP блоклох, хост тусгаарлах шийдвэрийг зөвшөөрөлтэйгөөр гаргана. Боломжтой үед төхөөрөмжийг шууд унтраахгүй, дэгдэмхий нотолгоог хадгална.

## 5. Eradication — Аюулыг арилгах

- [ ] Зөвшөөрөлгүй үүссэн backdoor хэрэглэгчийг шалгаж, батлагдвал устгах.
- [ ] Сэжигтэй scheduled task, SSH authorized_keys болон persistence механизмыг шалгах.
- [ ] Алдагдсан нууц үгийг шинэчлэх.
- [ ] Идэвхтэй session, token-ийг шаардлагатай бол хүчингүй болгох.
- [ ] Халдлагад ашиглагдсан буруу тохиргоо, эмзэг байдлыг засах.
- [ ] Хортой үйл ажиллагаа бүрэн арилсныг дахин шалгах.

## 6. Recovery — Хэвийн ажиллагааг сэргээх

- [ ] Системийн бүрэн бүтэн байдлыг шалгах.
- [ ] Шаардлагатай бол баталгаатай цэвэр backup-аас сэргээх.
- [ ] Эрх бүхий ажилтны зөвшөөрлөөр хостыг сүлжээнд буцаах.
- [ ] Хэрэглэгчийн эрх болон authentication тохиргоог шалгах.
- [ ] Wazuh Dashboard дээр нэвтрэлтийн давтан алдаа, сэжигтэй процессыг хянах.
- [ ] Дахин халдлага илрээгүй, үндсэн үйлчилгээ хэвийн болсныг баталгаажуулах.

## 7. Escalation — Шатлан мэдээлэх

| Severity | Нөхцөл | Хэнд мэдээлэх | Tier 1-ийн үүрэг |
|---|---|---|---|
| Low | Батлагдсан зөвшөөрөгдсөн туршилт | SOC Tier 1 | Нотолгоотой хаах |
| Medium | Давтагдсан нэвтрэлтийн алдаа, compromise батлагдаагүй | SOC Tier 2 | Triage, лог цуглуулах |
| High | Зөвшөөрөлгүй амжилттай нэвтрэлт сэжиглэгдсэн, нэмэлт сэжигтэй үйлдэлтэй | SOC Tier 2 + IR Lead | Шуурхай escalation |
| Critical | Domain admin compromise, олон хостод тархалт эсвэл өндөр нөлөөлөл батлагдсан | IR Lead + удирдлага | Яаралтай мэдэгдэх |

*Энэ хүснэгтийн нөхцөлүүд нь лабораторийн жишиг бөгөөд байгууллагын батлагдсан escalation matrix, SLA-г мөрдөнө.*

## 8. Баримтжуулалт

Дараах мэдээллийг incident record-д хадгална.

- Incident ID болон ангилал.
- Илрүүлсэн огноо, цаг (UTC).
- Холбогдох Wazuh alert, rule ID, Event ID.
- Хэрэглэгчийн нэр, IP, өртсөн хост.
- Timeline болон IOC.
- Хийсэн шинжилгээ, containment, recovery үйлдлүүд.
- Шийдвэр гаргасан болон зөвшөөрөл өгсөн ажилтан.
- Нотолгооны файлын зам, SHA256 hash.
- Chain of custody бүртгэл.
- Эцсийн төлөв, lessons learned.

## 10. Дүгнэлт

Энэхүү playbook нь SSH/RDP brute-force халдлагыг илрүүлэх, account compromise болсон эсэхийг шалгах, өртсөн системийн хамрах хүрээг тодорхойлох, containment, eradication, recovery болон escalation шийдвэрийг дарааллаар хэрэгжүүлэх заавар юм. Бодит лабораторийн Wazuh alert-уудыг ашиглаж, батлагдсан үйл явдал болон таамаглалыг тусад нь баримтжуулав.
