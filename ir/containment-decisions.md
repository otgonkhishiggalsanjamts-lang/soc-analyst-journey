
# Практик 14 — Containment шийдвэрийн дасгал

## 1. Зорилго

Wazuh Active Response ашиглан халдлагын сэжигтэй үйл ажиллагааг автоматаар хязгаарлах болон SOC шинжээчийн гар аргаар containment хийх аргуудыг харьцуулж, шийдвэр гаргах нөхцөл, давуу болон сул тал, үүсэж болох эрсдэлийг тодорхойлох.

## 2. Wazuh Active Response гэж юу вэ?

Wazuh Active Response нь тодорхой илрүүлэх дүрэм ажиллах үед урьдчилан тохируулсан хамгаалалтын үйлдлийг автоматаар гүйцэтгэх боломж юм.

Жишээлбэл, SSH үйлчилгээнд нэг IP хаягаас олон удаа амжилтгүй нэвтрэх оролдлого илэрч, Wazuh Rule 5712 ажиллавал тохиргооноос хамааран тухайн IP хаягийг firewall-аар түр блоклох боломжтой.

Энэ нь халдлагын үргэлжлэх хугацааг багасгах давуу талтай боловч буруу илрүүлэлтэд үндэслэн хууль ёсны хэрэглэгчийг блоклох эрсдэлтэй.

## 3. Автомат болон гар containment-ийн харьцуулалт

| Үзүүлэлт | Автомат containment | Гар containment |
|---|---|---|
| Гүйцэтгэх арга | Active Response урьдчилан тохируулсан үйлдэл хийнэ | SOC шинжээч нотолгоонд тулгуурлан шийдвэр гаргана |
| Хурд | Шуурхай | Хүний шинжилгээний хугацаа шаарддаг |
| Давуу тал | Давтагдсан халдлагыг хурдан хязгаарлана | Нөхцөл байдлыг олон талаас үнэлнэ |
| Сул тал | False positive үед буруу блоклолт үүсэж болно | Хариу арга хэмжээ удааширч болзошгүй |
| Хяналт | Дүрэм, тохиргооноос хамаарна | Эрх бүхий ажилтан шийдвэр гаргана |
| Тохиромжтой нөхцөл | Баталгаажсан, эрсдэл багатай үйлдэл | Өндөр нөлөөтэй, тодорхойгүй инцидент |

## 4. Автомат containment хэзээ аюултай вэ?

### 4.1. False positive

Хэвийн хэрэглэгч нууц үгээ олон удаа буруу оруулснаас brute-force дүрэм ажиллаж болно. Энэ үед Active Response тухайн хэрэглэгчийн IP хаягийг блокловол хууль ёсны хандалт тасалдах эрсдэлтэй.

### 4.2. Хуваалцсан IP хаяг

NAT, VPN болон байгууллагын proxy ашиглаж байгаа олон хэрэглэгч нэг гадаад IP хаягаар холбогдож болно. Тухайн хаягийг блокловол нэг хэрэглэгчээс гадна бусад хэрэглэгчийн үйлчилгээ тасалдаж болзошгүй.

### 4.3. IP spoofing болон DoS эрсдэл

Зарим төрлийн сүлжээний дохиололд эх IP хуурамчаар харагдах боломжтой. Ийм мэдээлэлд сохроор тулгуурлан блоклолт хийвэл хууль ёсны IP-г хааж, үйлчилгээ тасалдуулах эрсдэл үүснэ.

Тайлбар: TCP дээр баталгаажсан SSH нэвтрэлтийн оролдлогыг дурын spoofed IP-ээр амжилттай гүйцэтгэх нь энгийн биш. Иймээс spoofing-ийн эрсдэлийг логийн найдвартай байдал, эх сурвалжийн төрөлтэй уялдуулан үнэлнэ.

### 4.4. Чухал сервер болон удирдлагын IP

Администраторын IP, monitoring систем эсвэл сүлжээний үндсэн үйлчилгээний хаягийг автоматаар блоклох нь системийн ажиллагаанд сөргөөр нөлөөлж болно.

## 5. Лабораторийн бодит тохиолдлын шинжилгээ

### 5.1. Илэрсэн дохиолол

Практик 14-ийн A хэсэгт WIN-EP01 төхөөрөмж дээр дараах үйл явдлууд бүртгэгдсэн.

- Wazuh Rule 60204 — Multiple Windows Logon Failures.
- Rule level — 10.
- Windows Event ID — 4625.
- Хэрэглэгч — Administrator.
- Эх IP — 127.0.0.1.
- Logon Type — 2 (Interactive).
- MITRE ATT&CK — T1110 (Brute Force).

Олон удаагийн амжилтгүй нэвтрэлтийн дараа Event ID 4624 буюу амжилттай нэвтрэлт бүртгэгдсэн.

### 5.2. Containment шийдвэр

Энэ тохиолдолд 127.0.0.1 нь loopback хаяг бөгөөд нэвтрэлт тухайн компьютер дээрээс үүссэн байна.

Иймд уг IP-г firewall-аар автоматаар блоклох нь тохиромжгүй.

Мөн амжилтгүй болон амжилттай нэвтрэлтийн дараалал илэрсэн ч зөвшөөрөлгүй нэвтрэлт болсон нь батлагдаагүй.

### 5.3. Санал болгож буй арга хэмжээ

1. Windows Event 4625 болон 4624-ийн цаг, хэрэглэгч, IP, Logon Type-ийг харьцуулах.
2. Нэвтрэлт лабораторийн зөвшөөрөгдсөн үйл ажиллагаа байсан эсэхийг баталгаажуулах.
3. Event 4720, 4732 болон Sysmon-ийн бүртгэлээр дараагийн үйл ажиллагааг шалгах.
4. Зөвшөөрөлгүй хандалт батлагдвал Tier 2 болон IR Lead-д escalation хийх.
5. Эрх бүхий ажилтны зөвшөөрлөөр тохирсон containment арга хэмжээг хэрэгжүүлэх.

## 6. Шийдвэрийн хүснэгт

| Нөхцөл | Санал болгож буй шийдвэр | Үндэслэл |
|---|---|---|
| Баталгаажсан brute-force, гадаад IP | Хязгаарлагдмал хугацаатай автомат блоклолт боломжтой | Давтагдсан оролдлогыг хурдан хязгаарлах |
| Нэвтрэх алдаа, эх IP нь 127.0.0.1 | Автомат IP блоклолт хийхгүй | Loopback хаяг |
| NAT/VPN-ийн хуваалцсан IP | Гар шинжилгээ, баталгаажуулалт | Бусад хэрэглэгчид нөлөөлөх эрсдэл |
| Өндөр эрхтэй дансны compromise батлагдсан | Шуурхай escalation болон зөвшөөрөгдсөн containment | Өндөр эрсдэл |
| False positive батлагдсан | Блоклолт хийхгүй, alert-ийг баримтжуулах | Хэвийн үйл ажиллагаа |

## 7. Нотолгоо хадгалах

Containment шийдвэр гаргахдаа дараах мэдээллийг хадгална.

- Wazuh alert-ийн JSON.
- Windows Event ID, Rule ID, timestamp.
- Эх IP, хэрэглэгч, төхөөрөмжийн мэдээлэл.
- Шинжилгээ хийсэн ажилтан, цаг.
- Containment шийдвэрийн үндэслэл.
- Хэрэгжүүлсэн үйлдэл болон үр дүн.
- Холбогдох нотлох баримтын SHA256 hash.

## 8. Дүгнэлт

Автомат containment нь халдлагыг хурдан хязгаарлах давуу талтай боловч false positive, хуваалцсан IP болон чухал үйлчилгээний хаягийг блоклох эрсдэлтэй.

Гар containment нь илүү нарийвчилсан шинжилгээ хийх боломж олгодог ч шийдвэр гаргах хугацаа шаарддаг.

Практик 14-ийн лабораторийн Rule 60204 дохиололд эх IP нь 127.0.0.1 байсан тул автомат блоклолт хийхээс илүүтэй нотолгоог шалгаж, хүний хяналттай шийдвэр гаргах нь тохиромжтой гэж үзэв.

Энэ дасгалын хүрээнд бодит IP блоклолт хийгээгүй бөгөөд автомат болон гар containment-ийн шийдвэрийг онолын болон лабораторийн нотолгоонд тулгуурлан харьцуулсан.
